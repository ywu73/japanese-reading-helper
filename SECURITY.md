# Security and privacy reporting / 安全与隐私问题报告

## English

Use GitHub **Private Vulnerability Reporting** for a vulnerability that could
expose page data, broaden network transmission, execute unverified code, escape
the documented storage boundary, corrupt page DOM, bypass feature state, or
leave stale work active after disable. Do not include sensitive reproduction
details in a public Issue.

Include the affected version or commit, browser and userscript-manager versions
when relevant, a minimal reproduction, observed network/storage/DOM behavior,
and the expected privacy boundary. Ordinary bugs without a security or privacy
impact may use GitHub Issues.

This project does not publish a personal security email, response-time SLA, or
bounty promise. Private Vulnerability Reporting must be enabled in the GitHub
repository settings before this channel is available; that external setting is
still a release gate until explicitly completed.

## 简体中文

如果问题可能泄露页面数据、扩大联网传输、执行未经校验的代码、突破已记录的存储边界、破坏页面 DOM、绕过功能开关，或在关闭后继续运行过期任务，请使用 GitHub **Private Vulnerability Reporting**。不要在公开 Issue 中发布敏感复现细节。

报告中应包含受影响版本或 commit、相关浏览器和用户脚本管理器版本、最小复现、实际观察到的网络/存储/DOM 行为，以及预期隐私边界。没有安全或隐私影响的普通缺陷可以使用 GitHub Issues。

项目不公开个人安全邮箱，不承诺响应时限，也不承诺漏洞奖金。只有在 GitHub 仓库设置中启用 Private Vulnerability Reporting 后，该通道才可用；在明确完成该外部设置前，它仍属于发布门槛。
